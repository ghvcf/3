# 职桥 JobBridge · 港硕内地生跨境求职助手（静态原型）

面向港硕内地生的跨境求职辅助原型：纯前端、可离线运行，将《科技实现方式》所述的三层架构实现为可直接使用的单页站点。

| 文档中的层 | 文档中的原方案 | 本原型的实现 |
| --- | --- | --- |
| 呈现层 | Softr / Google Sites + 表格数据 | `index.html` + 手写 CSS（不引入框架与 CDN），岗位列表、筛选与详情均由前端渲染 |
| AI 能力层 | Coze 两个工作流（JD 关键词提取、术语释义） | `engine.js` 的**本地规则引擎**（关键词词典 + 正则，无外部依赖、响应即时、可离线）；另设可选的大模型接口，填写接口地址与密钥即可切换 |
| 数据聚合层 | HK Job Radar 式抓取 + 每日推送 | `data.js` 中的 `JOBS` 数据 + 订阅设置本地保存、简报复制、CSV 导出；真实抓取交由 GitHub Actions（见第五节） |

> 岗位为依据 JobsDB、LinkedIn 与 Indeed 公开岗位描述编写的**示例数据**，仅用于演示筛选、匹配与解析逻辑，**并非真实在招职位**。

---

## 一、运行方式

三种方式，任选其一：

1. **直接打开** `index.html`（无需安装依赖，断网可用）。
2. **本地服务器**（推荐，行为更接近线上环境）：
   ```bash
   # 在 jobbridge-site 目录中执行
   python -m http.server 8788
   # 随后访问 http://localhost:8788
   ```
3. 部署至静态托管平台（见第四节）。

页面数据（技能画像、主题、订阅设置、大模型配置）均保存在本机浏览器的 localStorage 中，不上传至任何服务器。

## 二、功能说明

### 1. 技能画像
- 选择技能标签后，岗位匹配度与 JD 技能缺口即时更新；
- 可设置目标方向、身份／经验与在港工作资格；选择「学生签注」时提示须先办理 IANG。

### 2. 岗位聚合列表
- 15 个示例岗位，标注来源渠道与发布时间；
- 支持关键词搜索、行业／类型／来源筛选，以及按匹配度、发布时间、薪酬排序；
- 每个岗位显示匹配度与缺口技能；「在解析器中打开」可将该岗位描述直接载入解析器；
- 展开岗位描述后，术语已标注，点击即显示释义。

### 3. JD 解析工具
粘贴任意岗位描述，输出四类结果：

| 栏目 | 内容 |
| --- | --- |
| 硬技能 | 由词典命中的技能词，点击标签可加入技能画像 |
| 软技能 | 沟通表达、抗压能力、跨部门协调等 |
| 隐性偏好 | 语种、经验年限、学历、到岗时间、本地经验、职责边界等潜台词 |
| 风险信号 | 签证不担保、纯佣金、无薪、资历错配、五天半工作、短期合约等，分 high / mid / low |

另附匹配度百分比、技能缺口清单与原文术语标注。

### 4. 术语释义（侧边抽屉）
- 74 条港式职场与金融合规术语（IANG、OT、KPI、KYC、跑数、埋数、出 trip…）；
- 每条含中文释义、语境示例与港硕应对建议；
- 支持关键词搜索与分类筛选；
- 岗位描述中被标注的术语，点击即跳转至对应词条。

### 5. 岗位简报订阅
本站为纯静态页面、不含后端服务，订阅功能以三种可落地的方式实现：保存设置（本机）、复制岗位简报（可直接粘贴至邮件或即时通讯工具）、导出 CSV（可由 Excel 打开）。
正式上线时按页面右侧的说明接入 Google Forms 或 Google Apps Script 即可。

## 三、目录结构

```
jobbridge-site/
├── index.html                 # 单页结构（首屏 / 画像 / 岗位 / 解析 / 订阅）
├── assets/
│   ├── css/style.css          # 全部样式（含深色模式、响应式、打印样式）
│   └── js/
│       ├── data.js            # ★ 数据：站点信息、15 个岗位、74 条术语
│       ├── engine.js          # ★ 规则引擎：JD 解析、匹配度、术语标注
│       └── app.js             # 交互：渲染、筛选、抽屉、订阅、可选大模型
├── preview-1.png              # 首屏截图
├── preview-2.png              # JD 解析截图
└── README.md
```

体积约 120 KB，无依赖、无构建步骤。修改内容通常只需改动 `data.js`。

## 四、发布上线（三种方式）

### A. GitHub Pages（常用方式）
1. 新建仓库，将 `jobbridge-site` 内的文件置于仓库根目录；
2. 在 `Settings → Pages → Build and deployment` 中，Source 选择 `Deploy from a branch`，分支选择 `main` 与根目录；
3. 约一分钟后，访问 `https://<用户名>.github.io/<仓库名>/`。

### B. Cloudflare Pages（国内访问通常较为稳定）
1. 登录 Cloudflare → Workers & Pages → Create → Pages → Upload assets；
2. 上传整个文件夹并执行 `Deploy`；
3. 获得 `https://xxx.pages.dev` 域名，可绑定自有域名。

### C. Netlify Drop（无需注册即可试用）
打开 <https://app.netlify.com/drop>，将文件夹拖入浏览器窗口，数秒后即生成网址。

> 上述平台的托管配额足以支撑小范围试用；纯静态站点不需要服务器与数据库。

## 五、接入真实岗位数据

只需修改 `assets/js/data.js` 中的 `JOBS` 数组，每项字段如下：

```js
{
  id: 'J01',                 // 唯一标识
  title: '数据分析师',        // 岗位名称
  company: '公司名',
  sector: '金融',             // 行业（同时用于筛选与订阅方向）
  loc: '金钟',
  type: '全职',               // 全职 / 实习 / 合约 / 兼职
  salary: 'HK$22,000–28,000',
  salaryMin: 22000,          // 用于「按薪酬」排序
  posted: '今天',             // 今天 / 昨天 / 3 天前 / 1 周前（用于排序）
  source: 'JobsDB',          // JobsDB / LinkedIn / Indeed
  lang: ['普通话', '英语'],
  fresh: true,
  skills: ['Excel', 'SQL'],  // 须与匹配度使用的技能名一致
  tags: ['应届可投', 'IANG 欢迎'],
  jd: `……完整岗位描述……`      // 使用反引号包裹，可跨行
}
```

若需批量接入，可让抓取脚本输出相同结构的 JSON，再以 `const JOBS = [...]` 引入。

**自动更新（对应文档中的「定时监控」）：** 在仓库中新增 `.github/workflows/daily.yml`，每日定时运行 Python 脚本抓取 JobsDB / LinkedIn / Indeed 的关键词结果，写入 `jobs.json` 后提交。GitHub Pages 将自动重新部署，整条链路无需服务器。

> 注意：抓取第三方站点前请先查阅其 `robots.txt` 与服务条款，控制请求频率，仅采集公开信息；更稳妥的做法是申请官方 API 或使用 RSS。

## 六、AI 能力的两条实现路线

### 路线一：本地规则引擎（默认）
`engine.js` 使用 91 条硬技能词典、15 类软技能词与约 25 条正则，将岗位描述拆分为四类结果。优点是不依赖密钥与网络、响应即时、结果可解释（可定位到触发词）；缺点是对全新表述存在漏检。

如需扩展，直接向以下三处添加词条即可：
- `HARD`：硬技能（`n` 为规范名，`a` 为同义词与英文写法）
- `SOFT`：软技能
- `parseJD()` 中的 `pushH()`（隐性偏好）与 `pushR()`（风险信号）

### 路线二：接入大模型（可选，按调用量计费）
在页面「JD 解析工具 → 可选配置：接入大模型」中填写三项：接口地址、模型名称、API Key（仅存本机）。接口需兼容 OpenAI 的 `/chat/completions` 协议，例如：

```
接口地址：https://api.deepseek.com/v1/chat/completions
模型名称：deepseek-chat
```

调用失败时自动回退至本地规则引擎，并提示原因。

**两点说明：**
1. 浏览器直连会暴露 API Key，仅适合本地自用；公开上线时应由后端或 Serverless 函数代理，并将密钥置于服务端。
2. 以 `file://` 打开时，部分服务商因 CORS 限制会拒绝请求；改用 `python -m http.server` 打开即可。若仍被拒绝，需在服务商控制台或自建代理处允许跨域。

## 七、设计取舍

- **不引入前端框架**：15 个岗位的规模，手写 DOM 渲染即可满足需求，可省去构建环节与首屏加载开销。
- **不引入外部字体与 CDN**：国内与校园网环境可能屏蔽 Google Fonts，全部采用系统字体，便于离线使用。
- **数据内联**：`data.js` 直接内联，以 `file://` 打开时不存在跨域问题。
- **规则引擎优先**：文档中 Coze 的思路成立，但在演示阶段，规则引擎能给出可解释、可复现的结果，亦符合原文「轻量化、可快速验证、可独立复现」的定位。
- **无障碍**：语义化标签、`aria-pressed`、键盘焦点样式、`prefers-reduced-motion`、跳转链接。
- **深色模式**：右上角 ◐ 切换，按手动选择记录于本机。

## 八、已知局限与后续工作

- 岗位为示例数据，尚未实现真实抓取与去重；
- 订阅功能仅实现本地保存与导出，尚未实际发送邮件（需 Google Apps Script 或后端）；
- 规则引擎对新型表述存在漏检；纯英文长文本的识别率相对较低；
- 尚未实现账号体系、收藏与投递记录；
- 未做搜索引擎优化（单页结构，如需被收录可拆分为多页或增加预渲染）。

建议优先实现「真实抓取 + GitHub Actions 每日更新」，此为实现文档中消解信息差主张的基础；其次为大模型接入与邮件推送。
